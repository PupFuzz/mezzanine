# Design-doc verifiers (review-time guards)

- `d1_appendix.py` — **not a verifier: the one parser for D1's captured-payload appendix (§ 17)**, imported by `verify-harness-facts.py` and by `bin/harness-fixture-drift.py`. Two consumers need the same population — every hook payload the appendix publishes, and whether each is a real capture or a DOCS-CITED stub — and written twice those parsers are free to disagree about what § 17 contains, which shows up as one gate reporting clean over a population the other one can see. Every structural fact is read from the document (the appendix is found by its own heading and its section NUMBER is derived, never typed; the capture/stub split is decided by which side of the DOCS-CITED heading a payload sits on) and every failure to read one **raises** rather than returning a smaller population: an unparseable block, a block with no `hook_event_name`, a payload parked outside the appendix or after the stub subsection, and an empty region are all refusals. Heading scanning is fence-aware, so a `#` line inside a code block cannot end a section early.
- `verify-event-schema.py` — structural: every JSON block parses, every internal anchor resolves, no review-finding ids or TODO/TBD markers leak into the doc. It also re-derives two populations the doc states rules over, rather than trusting the numbers written there: the enum-field population behind § 6.0's classification table, and the member counts behind § 6.14's two exempt capped objects — `predicates` and `selftest` carry no reduction rule *because* their worst-case serialization is below their caps, so a row added to § 9.4's predicate table or § 6.14's self-test member table moves that arithmetic and reds the gate, wherever the figure is quoted. Every capped object in a § 6 field table must state a reduction rule or its exemption, and § 6.0 rule 5's count of them is checked against the tables.
- `verify-harness-facts.py` — harness-fact: re-derives hook payload key sets and every harness enum's value set from the INSTALLED Claude Code binary on every run (no stored ground truth) and checks the doc's § 17 fixtures and enum-statement sites against them. **Which build is ground truth is D1's fact, read from D1's five declared-build sites, which must agree** — the tool states no version and no path of its own; it resolves `<versions dir>/<the build D1 declares>`, taking the versions directory from wherever `claude` on `PATH` resolves (override: `MEZZ_CLAUDE_VERSIONS`). Version-dependent by design, and fail-closed: when D1's declared build is not installed — the usual case, since the installer garbage-collects old versions — it reds with ONE line naming the build, what is installed, and the fix (re-capture per D1 § 6.0 obligation 2, or install that build). `MEZZ_HARNESS_BIN=<path>` inspects a different bundle and says on every run that a pass under it is evidence about *that* build, not about the one D1 declares. Nothing in it is pinned to a bundler-generated identifier: those are regenerated per build, and identifier resolution is module-scoped (never global first-match) because a bundled name is reused across modules — a global match resolved one enum to an unrelated array of shell dotfile names.
- `verify-fleet-state.py` — D2's gate: eleven guard classes over `docs/design/FLEET-STATE.md`, each re-deriving its population from the document's own tables, from the JSON blocks it publishes, or from D1 — byte figures by serialization, field tables against worked examples both ways, ENUM member reachability, counter closure, and § 12's numbers against their definition sites with a perturbation that proves each match can fail.
- `verify-floor.py` — D3's gate: eleven guard classes over `docs/design/FLOOR.md`, every population re-derived from D2 (and, for one set, from D1) rather than stored here. The six worth naming, because they are the document's headline claims made checkable: **G1** holds the honesty principle — every animation named anywhere has a row in the closed animation table, every row declares its class (`edge` or `held`, which selects its animation-log causality rule), and every row's driving fact is a field or message D2 actually declares, so an animation with no event cannot be written in good faith. **G7** holds render closure over **six** member sets — `render_state`, `unknown_reason` and the eighteen badges, plus `link_state` and `activity_state` from D2 § 8.2.1's bounds cells and `api_error_type`'s twelve from D1 § 6.4, which is where D2 sources it — each re-derived upstream and set-differenced against D3's tables in both directions, so a member with no render, and a render for a member no input can select, both red the gate. **G9** holds the delivery contract — D2 § 6.5's ten non-version-bearing members are re-derived from that section's own table, and a D3 render row that sources one without a marker **legal for that member** reds the gate, because a field-existence check cannot see a delivery contract: all ten exist, and a client's copy of them freezes between full objects. `dark-only` is granted to `delivery.last_receipt_at` alone, re-derived from D2's own carve-out sentence, and the two tables that render on the **desk** must carry it rather than substituting the drill-down's `fetch-fresh`. **Its table population is derived, not listed** — every markdown table in the document is found structurally, a § 5 table the gate has no source column for reds rather than being skipped, and membership is keyed on a row's **line number** rather than on its text, so a byte-identical copy in an unmapped table cannot test as already-checked. A table row anywhere else that names one of the ten reds unless it declares itself `named-not-rendered`; a marker written into such a row exempts nothing, and the only two rows entitled to carry one without rendering are recognised by **role** — the marker table's own rows, whose key cell is the marker, and § 12's guard-class table's rows. The **rule's own scope claim** — § 2.4's sentence enumerating the tables it holds over — is set-differenced against the gate's column map in both directions, because that sentence is a second home for the same fact and is the home that went false. That inversion is the repair for the class the stored list minted: § 5.6 was added with six ten-sourcing rows, the list did not contain it, and the gate reported clean while the document claimed the rule held over every § 5 row; § 7.1 was the same shape one table further out, its two desk renders of the receipt age admitted by a bare token. **G5** holds the acceptance tests' build order: the artifact→step map comes from Appendix B's own bold Artifact names, what each test reads from its own `Reads:` clauses, and which half a gate gates from the Gate cell's qualifier — so every declared half is checked against every artifact it declares, at every step that gates it, and an unqualified mention gates the whole test, which is what stops a late co-gating from discharging an early one. **G10** closes the null render both ways against D2 § 8.2.1's own `Null? yes` column, so a nullable member with no stated null render, and a null render for a member D2 does not mark nullable, both red. **G11** holds a **worked example against the rule statement that governs it**, which is a class D3 had no guard for at all, and it now covers **two** facts — each with an owning table, each with instances read out of the document. **(a) The composed `api_error_type` line:** § 7.6's twelve member/phrase pairs are re-derived from that table and the two sites rendering one are held against them — § 7.1's `stalled` cell, which must carry the member verbatim with its phrase beside it, and § 5.1's *rendered verbatim* row, whose illustration must be a member and not a phrase. Both were false: the cell published the phrase with the raw value elided, against § 7.6's own column heading, § 5.4, § 5.1 and the same row's `Never` column, and the illustration showed the phrase as its example of verbatimness — neither could be differenced against anything, because the **composition** of the line was published at no site at all, which is why § 7.6 now publishes it once. **(b) Where the `activity_state` currency label is drawn:** the placement phrase is re-derived from § 7.6's five `activity_state` rows, which must agree with one another — if they do not, the tool reports the rule as disagreeing with **itself** and judges no instance, because that is a rule-against-rule amendment and not a defect in any example — and every worked instance elsewhere must state that same placement. **Its population is structural, never listed:** any table cell carrying a *was:* span or naming the `activity state` in words, so a fourth site added tomorrow is in it the moment it exists, and a run that finds **none** reds rather than reporting clean over an empty set. Two tables are out of it **by role** and both exclusions are load-bearing: § 7.6's own `activity_state` rows are the **rule**, not an instance of it, and § 12's guard-class rows **describe this gate** — a row documenting a guard necessarily quotes the defect it guards, so a recognizer that read one would fail on the *correction* and pass a silent fix, getting redder the more honestly the write-up is done. That is not hypothetical: it fired on this leg's own § 12 row before the carve-out existed. ⚠ **And one hole is declared rather than closed:** the leg asks whether a cell CONTRADICTS § 7.6, never whether it states the placement at all, so a cell that re-words the placement out of the recognizer's vocabulary escapes by matching nothing. The stricter tier was written, run and removed — it red on § 7.1's own `catching_up` cell, which says the form is drawn *under this line* while pointing at § 7.3 and § 7.6: correct, and a **mention** rather than a placement, which no structural test here can tell apart, so enforcing the literal would have been a style rule that reds on a careful paraphrase and passes a careless overwrite. That leg exists because § 7.3's `catching_up` and `disabled` rows said the activity state renders *in the label only* while § 7.6 — the section that owns the form — said *under the label* in five rows: a one-element reading under which a `catching_up` desk draws `activity.last_event_time` twice on one line, and § 7.6's own `link_state` row had drifted with them, which is the sibling nobody had named. Every predicate is fed its own defect on every run and must reject it; the placement predicate builds its counter-example by substituting a preposition the rule does **not** use, chosen from the recognizer's own alternation, so no answer is stored here. Its controls have been seen red six ways — each § 7.3 row reverted, § 7.6's `link_state` row reverted, one § 7.6 rule row drifted (the *rule disagrees with itself* branch), all five rule rows moved with the instances left behind (the instances red, which is the leg following the **owner** rather than a stored string), and the rule table's header renamed so the rule is never read.

- `floor-preview.selftest.mjs` — the RATIFIED ARTIFACT's gate, and the only one here that judges **code** rather than a document: `docs/design/floor-preview/floor-preview.html` is what card#7341 builds FROM, so a rule D3 states and the artifact does not implement ships into the build — **except where the artifact DECLARES that it does not, which is the scope table this gate set-differences against § 5.4's six membership-tested render surfaces in both directions** (a surface D3 gains with no row reds; a row for a surface D3 does not publish reds), because the artifact is a reference implementation of a declared subset and *absent because out of scope* is otherwise indistinguishable from *absent because missed*. It also holds the two lookups keyed on **identity** rather than on a member set — a seat's `desk` against the floor map's slots, and an install against the client's theme map — against § 3.2's overflow rule and § 9 F13: a labelled overflow row, a notice reading *floor map is short N desks*, and never a dropped seat. It evaluates the artifact's own script in a stub DOM and holds three things. **Neither the member sets nor what they render are stored here**: three published tables are re-derived from D3 on every run — § 7.1's ten `render_state` members **with their Label line column**, § 7.1's seven `unknown_reason` sentences, and § 7.6's twelve `api_error_type` phrases — and each is compared **cell by cell**, so a member D3 gains with no row reds the gate, and so does a rendered string that has drifted from the document's. **That second half is the one a first revision of this gate got wrong**: it parsed only the member NAMES while three surfaces claimed it checked the sentences, so a sentence rewritten to say the opposite of D3 ran green — which is why each set now has a mutation control of its own rather than a claim. **The table's shape**: every row carries every cell, names a chip class the artifact's own stylesheet defines, and declares whether its desk draws a character — so a row that omits a cell is loud rather than an `undefined` at a render site. **The behaviour**: a probe seat is driven through all ten members — with D3's own worked example values, so the rendered line is compared to § 7.1's Label line column literally — through the null edges § 7.1 and § 5.6 state, through the sibling membership sets on `unknown_reason` and `api_error_type`, and through eight values that are not members at all, and the DOM the artifact produces is read back: § 5.4's unrecognised render, carrying the raw string, with the desk treated as not-current for an unrecognised value in **any** of those fields, never the nearest known member and never a crash. **Where the overflow row LANDS**, which the rest of it cannot see: asserting that a homeless seat's desk is drawn says nothing about where, and the row shipped drawn over sola's tea bar with every structural check green. D3 § 3.2 puts that row **below the floor** — a position stated in § 3.2 and not in F13's summary row, which is how four passes read the rule and missed it — so the artifact extends an overflowing floor's canvas by the band and draws the row in that appended strip, and this gate holds the boundary between the two regions: **nothing the floor emits reaches below `FH`, and nothing the band emits rises above it**, one scalar per floor in each direction, at any row length. That replaced a pairwise desk-versus-furniture collision layer, the per-theme `overflow` origins it checked and the declared row capacity beside them — all of which were machinery for a row drawn inside the floor, and none of which is a question once the row is where § 3.2 puts it. ⛔ **An unmeasurable shape makes the assertion FAIL**: the layer it replaces claimed *unmeasurable is loud* and the claim was false in four demonstrated forms — an arc command, a `<polygon>`, a `NaN` width and an unmodelled `stroke-width` — three of which stayed green with an obstacle drawn on the desk, because each fell through a silent `else` and left a shorter list of boxes that still looked clean. Every element is now classified, a tag it does not own is NAMED, and the answer is *not measured* rather than a number. Anchored mutations prove every layer can fail — each required to go red on its own, because the loud defect throws first and a check that only ever ran behind a crash, or only ever ran green, is a check nobody has seen work — and **how many checks and how many controls the file carries is counted at run time and printed on its own last line**, so that figure lives in one place instead of drifting through three. ⚠ **It is not evidence about the composed page**: there is no browser and no HTML parser, so nothing is laid out, painted or seen — the assertions are on the values the artifact emits, and jsdom would not close that gap either (it does no layout). That gap is the next verifier's, not this one's; what this one owns of it is the single arithmetic overlay fact, the thought bubble's **anchor** above a band desk, held against **the band header's own re-derived extent rather than against `FH`** — `FH` is where the strip begins and the strip begins with the header, so the weaker threshold passed a bubble sitting on it.

- `floor-preview.browser.mjs` — the same artifact's **composed-layout** gate, and the only verifier here that drives a real browser (headless Chromium; `--chrome <path>` or `$CHROME`, otherwise found in the playwright cache — **no browser is a FAILURE, never a skip**, because a gate that reports nothing when its instrument is missing is the false-clean shape the whole file exists against). It exists because **the artifact has two coordinate systems**: the floor, desks and band are SVG **user units**, while the thought bubbles, nameplates, markers and hit targets are HTML positioned over that SVG but **sized in CSS pixels**. A user unit and a CSS pixel are not the same length and their ratio is not a constant, so nothing reading SVG attributes can answer *does the bubble cover the header* — which is why four rounds of card#7965 each moved SVG content correctly and each re-collided with the layer no gate measured, with `floor-preview.selftest.mjs` green every time: the row over the tea bar, then below the floor with its bubble on the band's own arithmetic line and its nameplate hanging out of the strip. **The fix is not a better model of the two systems but to stop having two**: in a composed page `getBoundingClientRect()` returns both layers in ONE space, so the question is a rect intersection between things that were actually laid out — no transform parser, no arc bounding, no stroke padding, no *not measured* category, none of which is a question once the browser has done the layout. It asserts, per case: the client↔user-unit map **agrees with a measured element** before any region is derived through it; **no overlay rect intersects any line of the band's header**, measured as the browser laid the text out, glyph widths and all; **every overlay is inside the storey region its own `data-band` declares**, so the artifact's claim about which region an overlay belongs to is checked rather than believed; **every child of `#world` is either judged or a declared animation affordance**, so a new overlay class nobody tagged reds rather than sitting outside every check; and that the sweep really reached a band overlay and a header. Its population is **two room widths × each floor's own fit-floor framing plus the whole-building framing** — widths, because `#world` carries `transform:scale(z)` and therefore scales the SVG and the overlays together, making an overlay's size in user units a function of the room's width alone; the gate **measures that invariance** across all six cases rather than asserting it, and derives the narrowest room the band's budget carries down to instead of storing the figure. Its controls **re-mint the round's two defects from their own pre-fix constants** and require each to go red on its own message, plus a floor-side containment defect, a lying `data-band`, and an untagged overlay. ⚠ It measures **boxes, not ink**: opacity, z-order, fill and legibility are outside it, and two rects that do not intersect can still look wrong — how any of it *looks* is still verified by opening the file.

Each verifier hard-codes its own document and none of them is modified when another lands: widening a working guard to a second document is a change to that guard and belongs in its own round.

All were seen to fail on planted defects before being trusted (D1 review rounds 1–3; D2's and D3's plant runs are recorded on their own PRs). Run the verifier for a document before approving any change to it. D1's AT-21 is the separate BUILD-time obligation; these are the review-time guards.
