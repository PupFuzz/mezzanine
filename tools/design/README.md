# Design-doc verifiers (review-time guards)

- `verify-event-schema.py` — structural: every JSON block parses, every internal anchor resolves, no review-finding ids or TODO/TBD markers leak into the doc. It also re-derives two populations the doc states rules over, rather than trusting the numbers written there: the enum-field population behind § 6.0's classification table, and the member counts behind § 6.14's two exempt capped objects — `predicates` and `selftest` carry no reduction rule *because* their worst-case serialization is below their caps, so a row added to § 9.4's predicate table or § 6.14's self-test member table moves that arithmetic and reds the gate, wherever the figure is quoted. Every capped object in a § 6 field table must state a reduction rule or its exemption, and § 6.0 rule 5's count of them is checked against the tables.
- `verify-harness-facts.py` — harness-fact: re-derives hook payload key sets and every harness enum's value set from the INSTALLED Claude Code binary on every run (no stored ground truth) and checks the doc's § 17 fixtures and enum-statement sites against them. **Which build is ground truth is D1's fact, read from D1's five declared-build sites, which must agree** — the tool states no version and no path of its own; it resolves `<versions dir>/<the build D1 declares>`, taking the versions directory from wherever `claude` on `PATH` resolves (override: `MEZZ_CLAUDE_VERSIONS`). Version-dependent by design, and fail-closed: when D1's declared build is not installed — the usual case, since the installer garbage-collects old versions — it reds with ONE line naming the build, what is installed, and the fix (re-capture per D1 § 6.0 obligation 2, or install that build). `MEZZ_HARNESS_BIN=<path>` inspects a different bundle and says on every run that a pass under it is evidence about *that* build, not about the one D1 declares. Nothing in it is pinned to a bundler-generated identifier: those are regenerated per build, and identifier resolution is module-scoped (never global first-match) because a bundled name is reused across modules — a global match resolved one enum to an unrelated array of shell dotfile names.
- `verify-fleet-state.py` — D2's gate: eleven guard classes over `docs/design/FLEET-STATE.md`, each re-deriving its population from the document's own tables, from the JSON blocks it publishes, or from D1 — byte figures by serialization, field tables against worked examples both ways, ENUM member reachability, counter closure, and § 12's numbers against their definition sites with a perturbation that proves each match can fail.
- `verify-floor.py` — D3's gate: ten guard classes over `docs/design/FLOOR.md`, every population re-derived from D2 (and, for one set, from D1) rather than stored here. The five worth naming, because they are the document's headline claims made checkable: **G1** holds the honesty principle — every animation named anywhere has a row in the closed animation table, every row declares its class (`edge` or `held`, which selects its animation-log causality rule), and every row's driving fact is a field or message D2 actually declares, so an animation with no event cannot be written in good faith. **G7** holds render closure over **six** member sets — `render_state`, `unknown_reason` and the eighteen badges, plus `link_state` and `activity_state` from D2 § 8.2.1's bounds cells and `api_error_type`'s twelve from D1 § 6.4, which is where D2 sources it — each re-derived upstream and set-differenced against D3's tables in both directions, so a member with no render, and a render for a member no input can select, both red the gate. **G9** holds the delivery contract — D2 § 6.5's ten non-version-bearing members are re-derived from that section's own table, and a D3 render row that sources one without a marker **legal for that member** reds the gate, because a field-existence check cannot see a delivery contract: all ten exist, and a client's copy of them freezes between full objects. `dark-only` is granted to `delivery.last_receipt_at` alone, re-derived from D2's own carve-out sentence, and the two tables that render on the **desk** must carry it rather than substituting the drill-down's `fetch-fresh`. **Its table population is derived, not listed** — every markdown table in the document is found structurally, a § 5 table the gate has no source column for reds rather than being skipped, and membership is keyed on a row's **line number** rather than on its text, so a byte-identical copy in an unmapped table cannot test as already-checked. A table row anywhere else that names one of the ten reds unless it declares itself `named-not-rendered`; a marker written into such a row exempts nothing, and the only two rows entitled to carry one without rendering are recognised by **role** — the marker table's own rows, whose key cell is the marker, and § 12's guard-class table's rows. The **rule's own scope claim** — § 2.4's sentence enumerating the tables it holds over — is set-differenced against the gate's column map in both directions, because that sentence is a second home for the same fact and is the home that went false. That inversion is the repair for the class the stored list minted: § 5.6 was added with six ten-sourcing rows, the list did not contain it, and the gate reported clean while the document claimed the rule held over every § 5 row; § 7.1 was the same shape one table further out, its two desk renders of the receipt age admitted by a bare token. **G5** holds the acceptance tests' build order: the artifact→step map comes from Appendix B's own bold Artifact names, what each test reads from its own `Reads:` clauses, and which half a gate gates from the Gate cell's qualifier — so every declared half is checked against every artifact it declares, at every step that gates it, and an unqualified mention gates the whole test, which is what stops a late co-gating from discharging an early one. **G10** closes the null render both ways against D2 § 8.2.1's own `Null? yes` column, so a nullable member with no stated null render, and a null render for a member D2 does not mark nullable, both red.

- `floor-preview.selftest.mjs` — the RATIFIED ARTIFACT's gate, and the only one here that judges **code** rather than a document: `docs/design/floor-preview/floor-preview.html` is what card#7341 builds FROM, so a rule D3 states and the artifact does not implement ships into the build. It evaluates the artifact's own script in a stub DOM and holds three things. **The member set is not stored here**: `render_state`'s ten and `unknown_reason`'s seven are re-derived from D3 § 7.1's own tables on every run and compared against the artifact's table in order, so a member D3 gains with no row in the artifact reds the gate rather than going silently unrendered. **The table's shape**: every row carries every cell, names a chip class the artifact's own stylesheet defines, and declares whether its desk draws a character — so a row that omits a cell is loud rather than an `undefined` at a render site. **The behaviour**: a probe seat is driven through all ten members, through the null edges § 7.1 and § 5.6 state for them, and through eight values that are not members at all, and the DOM the artifact produces is read back — § 5.4's unrecognised render, carrying the raw string, treated as not-current, never the nearest known member and never a crash. Its controls re-mint each of the two silent defects card#7943 closed and require the sweep to go red under each independently, because the loud one throws first and a check that only ever ran behind a crash is a check nobody has seen work. ⚠ **It is not evidence about the picture**: there is no browser and no HTML parser, so nothing is laid out, painted or seen — the assertions are on the values the artifact emits, and jsdom would not close that gap either.

Each verifier hard-codes its own document and none of them is modified when another lands: widening a working guard to a second document is a change to that guard and belongs in its own round.

All were seen to fail on planted defects before being trusted (D1 review rounds 1–3; D2's and D3's plant runs are recorded on their own PRs). Run the verifier for a document before approving any change to it. D1's AT-21 is the separate BUILD-time obligation; these are the review-time guards.
