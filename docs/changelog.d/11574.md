- **card#11574** — **A tool call the reporter fills in itself is checked like any other, so one long id no longer loses a batch.** When a tool finishes and `fleet-reporter` holds no record of it starting, it fills in the start itself. That filled-in start took the tool's name and the harness's tool-call id straight from the finishing hook, so a name off its pattern reached the wire unchanged, and an id over the 64-byte bound had the site refuse the whole batch with `422` and its events lost. The start and the finish now read the call through one reader: a name off its pattern is sent as `INVALID_TOOL_NAME` and counted `invalid_tool_name`, and an id over 64 bytes is sent as empty, as the start has always done. A finished tool with an odd name also pairs with its own start by name instead of being filled in. The reporter moves to `0.6.5` (`fleet-reporter/UPDATES.md`). D1 § 6.6 states the rule.
