- **card#13117** — **The Seat tokens page saves a token file that names the seat alone, and the installer and the reporter know a seat by its seat id alone.** The saved `mezzanine-reporter-token` now holds three lines — `token`, `ingest_url` and `seat_id`, with no `install_id` — and the page names the installer it needs: reporter `0.7.0` or later. A token file saved before this change still installs, and its `install_id` is not written to the config. A token rotation or `add-site` compares the file's seat id with the config's and nothing else, so a seat the console places in another room rotates its token like any other; `--install-id` is no longer an `install.js` flag. A seat installed from the new file sends no `install_id`; a seat installed earlier keeps its config and keeps sending its value, with no reinstall. The reporter is `0.7.0`: pull the checkout and run `node fleet-reporter/install.js` on each seat. Upgrade warnings: an installer older than `0.7.0` refuses the new file because it carries no `install_id` line; its message says to treat the token as exposed, but nothing was written and the token is safe: update the checkout and run it again. Rolling the server back past the seat-id-only ingest while a seat installed from the new file is reporting leaves that seat's batches refused until the server is redeployed.
