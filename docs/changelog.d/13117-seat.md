- **card#13117** — **A seat is known by its seat id alone, across the whole site: a token is issued for a seat id, the ingest checks the seat id alone, and a new seat starts in no room.** Every reporter already installed keeps working with no reinstall and no new token: the `install_id` a reporter sends on its batches and events is accepted and no longer read. Issuing a token takes the seat id only — the console's *Seat tokens* form has one field, and the command is `php artisan mezzanine:ingest-token:issue <seat_id>` — and an id that is already live is a re-issue for that seat, named with its room and last receipt; a retired id is never issued again. A new seat is listed under `unassigned` and drawn on an implicit floor of that name until the console places it in a room. `mezzanine:retire`, `mezzanine:rebuild` and `mezzanine:seat-board-user` take `--seat=<seat_id>`, and `mezzanine:coord-hook:issue` takes `--scope=room --room=<room key>` in place of `--scope=install --install=…`; existing coordination hooks are migrated to the `room` scope. `GET /api/fleet/seats/{seat_id}` and `…/{seat_id}/timeline` are added beside the two-segment routes, which stay and now ignore their first segment; the snapshot keeps `api_version` 1, its `installs[].install_id` is now the seat's room, and it gains a group `unassigned` whenever a seat is in no room. Upgrade warnings: the migration refuses, changing nothing, while two LIVE seats share one seat id, while the stored layout places a room keyed `unassigned`, or while an unrevoked coordination hook or a current room map is bound to an install named `unassigned` — roll the deploy back, retire the duplicate, edit the layout, revoke the hook or remove the map, then redeploy; a consumer that selects seats by `installs[].install_id` (the agent webhook bridge's idle nudge) should select by `seat_id` instead. Rolling back re-homes every seat issued since the upgrade into an install named `unassigned`, which is the floor it was already drawn on.
