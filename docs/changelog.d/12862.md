- **card#12862** — **`laravel/framework` moves from v13.34.0 to v13.40.0, past the low-severity advisory GHSA-63hm-g96r-2m2q (task output injection through the Concurrency facade's process driver).** Mezzanine does not call the Concurrency facade, and none of its other Composer packages do either, so the advisory's code path is not reachable from the app; the update closes it all the same. Version 13.36 and later require `laravel/prompts` ^0.3.25, so `laravel/prompts` moves with it, from v0.3.23 to v0.3.26. **`symfony/mime` moves from v8.1.5 to v8.1.10, past the medium-severity CVE-2026-45070 (email header injection through non-token characters in MIME parameter names); Mezzanine builds its two-factor reset email with it.** **`symfony/http-foundation` (from v8.1.9), `symfony/http-kernel`, `symfony/routing` and `symfony/serializer` (each from v8.1.5) move to v8.1.11, past the advisories published on 2026-11-04.** In `symfony/http-foundation`, two apply to code Mezzanine runs: GHSA-5mx8-mwrp-5693 (a request path that can make the base URL start with a host the client chose; Laravel builds absolute URLs from that base, the link in the two-factor reset email among them) and GHSA-3h27-hjv7-fqjx (a path rule a web server enforces in front of PHP can be bypassed by appending the path to the script name, which matters only where the deployment's web server enforces such rules). It does not reach the other two there: CVE-2026-118514 (a HEAD request bypassing method-restricted request matchers) applies to Symfony's own request matchers, which nothing in the app uses, and GHSA-xg2q-4rrq-657q (the `private_ranges` trusted-proxy shortcut) applies only to an install that trusts proxies, which Mezzanine configures none of. GHSA-wg5q-m2ww-f3c9 in `symfony/http-kernel` concerns Symfony's inline fragment rendering, which Laravel does not use. CVE-2026-118516 in `symfony/routing` concerns host placeholders in compiled URL matchers, and Mezzanine declares no host-bound routes. CVE-2026-118515, GHSA-pxj9-jh84-vhm5 and GHSA-hqp2-7rr8-hf26 in `symfony/serializer` concern its uploaded-file, data-URI and object normalizers; its only callers in the lock are the passkey libraries, and with Fortify's passkeys feature disabled their routes are not registered. Every other locked package keeps its version, and `composer.json` is unchanged. A read of the framework's release notes for 13.35 through 13.40 found one change in a path Mezzanine's own code relies on: a deadlock or lock-wait timeout inside a NESTED transaction now rolls back to that transaction's savepoint before Laravel rethrows it (laravel/framework#62248). **Upgrade:** run `composer install` on deploy so the vendored packages match the lock.
