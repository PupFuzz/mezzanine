- **card#13171** — **`laravel/framework` moves from v13.40.0 to v13.42.0, past the two medium-severity advisories GHSA-6rv8-qj5v-p8ch and GHSA-v5ch-g375-82r6, through either of which an expired temporary signed URL could still be accepted.** The first adds a second `expires` field through numeric-keyed parameters passed to `signedRoute()` or `temporarySignedRoute()`; the second drops `expires` from the parsed query by exceeding PHP's `max_input_vars`. Both are fixed in 13.41.0, and 13.42.0 changes only the version number over it. Mezzanine creates no signed URLs, puts no route behind the `signed` middleware, and leaves Fortify's email verification off, so neither code path is reachable from the app; the update closes them all the same. Every other locked package keeps its version, and `composer.json` is unchanged. A read of the framework's changes for 13.41 and 13.42 found one in a path Mezzanine runs: Mezzanine stores its sessions as JSON, and a session value holding an invalid UTF-8 byte, such as a malformed `Referer` header Laravel saves as the intended URL, now has that byte replaced instead of emptying the whole session and signing the user out (laravel/framework#62378). **Upgrade:** run `composer install` on deploy so the vendored packages match the lock.
