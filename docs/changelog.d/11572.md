- **card#11572** — **A seat whose batches carry a non-ASCII `reporter_version` or `runtime_version` stays on the floor.** Both values are stored in ASCII columns of `batches`. A value within the 24-byte limit that was not ASCII failed the store, and the ingest answered `503 server_error` with `detail` `store_failed`. The reporter retries that answer with the same batch, and every batch from a seat carries the same versions, so the seat sent nothing that landed until its version changed. The ingest now stores `NULL` for such a value, counts it on the seat as `format_refused.reporter_version` or `format_refused.runtime_version`, and accepts the batch with its events. A seat stored with a `NULL` `reporter_version` reads as one that has reported no build, so it carries no `update_required` badge. An ASCII value is stored exactly as sent, and a value over 24 bytes, an empty one or a non-string is refused with `422 invalid_batch` as before. A migration makes the two `batches` columns nullable, online (`ALGORITHM=INPLACE, LOCK=NONE`), and the deploy's `migrate` runs it.
