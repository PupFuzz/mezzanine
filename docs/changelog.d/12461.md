- **card#12461** — **Re-issuing a seat's token while the same seat is being retired completes both actions in turn, without a database deadlock error.** Before this change, running `mezzanine:ingest-token:issue` (or issuing from the console's *Seat tokens* page) for a seat at the moment it was being retired, from the console or with `mezzanine:retire`, could make MariaDB stop one of the two with `ERROR 1213 Deadlock found`: a failed re-issue had to be run again, and a retirement retried it itself. The re-issue now waits for a retirement already under way; when that retirement commits, the re-issue is refused because the seat is retired, as for any retired seat, and no token is written. Nothing changes in the schema, the commands' output or their exit codes. (`docs/design/FLEET-STATE.md` § 6.5 and § 6.13; `App\Fleet\SeatLock`.)
