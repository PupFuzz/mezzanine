- **card#12476** — **Upgrading the reporter restarts a flusher that is still running the previous build, instead of reporting it as current.** `node fleet-reporter/install.js` judged which build the running flusher used by the time the flusher wrote into its lock, which comes after the flusher has read its script. A flusher that read the previous `fleet-reporter.js` a moment before the installer replaced it, and took its lock just after, read as the new build: the installer printed `INSTALLED`, and the seat kept sending under the previous version, with the site's `update_required` badge, until that flusher next restarted. The flusher now records in `flusher.lock` the instant its process began (`began_at`), and the installer stamps the artifact's install time after the file is in place and compares the two. The failure first reported here, a freshly restarted flusher read as the previous build, came from the earlier runbook's `/proc` clock and was already gone with `install.js`. Reporter `0.6.2` (`fleet-reporter/UPDATES.md`). **Upgrade:** deploy the server (its `current_reporter_version` is `0.6.2`, so a seat on `0.6.1` shows the `update_required` badge until it upgrades), then on each seat pull the checkout and run `node fleet-reporter/install.js` with no arguments.
