# Changelog

Every PR whose title or branch carries a `card#NNNN` token owes a line-initial
`- **card#NNNN** — …` bullet under `## [Unreleased]`, **in the same PR**. A PR that names no
card owes nothing. `docs/PLAN.md § 4` owns that rule and the reasoning behind it, including
why the bullet must be line-initial; `docs/VERSIONING.md` owns when a release collects these
entries and retitles the section.

⛔ **Enforced since 2026-08-30 by `bin/release-pr-guard.py` R4**, on every PR — for seven days
before that it was prose, and six cards' work merged with no entry at all. The two cases that
owe nothing are a PR into `main` (the release retitles this section) and a PR that REMOVES a
card's bullet (a revert of unreleased work); both are argued in that file's docstring. **R5**
holds this file's SIZE under `1 MiB − the bytes it grew in the last 14 days`, so it reds while
there is still time to archive released sections rather than after the contents API has begun
returning it empty. **R6** (card#9707) gives this section a third reader: on a release PR it
compares the cards bulleted here on `dev` against the head's changelog, so a release cannot
quietly ship with fewer cards than `dev` holds. **R7** (card#9814) refuses a release PR whose
copy of this file carries more than two released sections, and so enforces the archiving below.

Sections are newest-first: `[Unreleased]` collects what has landed on `dev` since the last
release, and a release retitles it (`docs/VERSIONING.md § Release flow` step 4).

This file holds `[Unreleased]` and the latest released section only. Every older release is one
file per tag under [`docs/changelog/`](changelog/) — `ls docs/changelog/` lists them — moved there
verbatim by release flow step 13 (`docs/VERSIONING.md`), which R7 enforces. R5 gates this file's
size; `docs/PLAN.md § 4` says why the archive files need no gate of their own beyond R7's backstop.

## [Unreleased]

- **card#12260** — **The repository's docs, changelogs, code comments, tests and fixtures carry no reference to the fleet's private coordination repository, and a CI check keeps it that way.** Each decision that cited a coordination thread is now stated in its own words. The new `No coordination-repository references` workflow runs `bin/no-roundtable-refs.py`, which fails a pull request that adds a reference in any tracked file; one reference inside the framework-managed block of `CLAUDE.md` is listed as an exemption until the framework's template drops it. Nothing an installer runs changes.
- **card#12180** — **One `fleet-reporter` install reports to up to four Mezzanine sites at once, such as production and the sandbox, so the same desk is on both floors.** The seat config gains a multi-site form: a `sites` list of up to four sites, each with its own `name`, `ingest_url`, `token`, `ca_file` and `proxy_url`, while `install_id` and `seat_id` stay the seat's, and each site issues the seat its own token for that same pair. An existing single-site config keeps working unchanged and is read as one site named `default`. Every site receives every event and only its own outcomes: a site that is down, slow, rate-limiting or refusing holds back nothing that another site receives, a spool bucket dropped while one site lags is counted as lost on that site alone, and each site's heartbeat carries that site's own backlog, counters and network checks. The hooks still append each event once, whatever the number of sites. The installer's writer in `fleet-reporter/INSTALL-LINUX.md` Step 2 now writes the multi-site form, adds a site with `FR_MODE=add-site`, and replaces one site's token with `FR_MODE=set-token`, in both cases checking the result with the reporter's own validation before it replaces the file. A seat reporting to one site sees these changes: the heartbeat is now sent as the first event of each request, so `events_sent` exceeds `events_emitted` by the number of heartbeats, and a site coming back from an outage receives no backlog of stale heartbeats; a batch that is retried is resent with its first attempt's `batch_id` and bytes, so a retry after the site committed it is answered as a duplicate and can no longer put other events under the sequence numbers the site holds; `state.json` holds the request in flight, so it is up to one batch larger; the quarantine and marker files are named for the site (`quarantine/rejected.default.jsonl`, `REJECTED.default.txt`); `selftest` adds the `token_accepted` check and a block per site, and a refused token now exits `1`; the site's own `401 unauthenticated` or `403 identity_mismatch` stops that site's sending until the flusher is restarted on a corrected token, keeping every unsent event, where it used to quarantine each batch; and an answer the ingest never gives — a `404` from a mistyped path, a proxy's error page, a `200` — is now retried, so the site stalls visibly instead of having its batches quarantined. A site whose `ingest_url` is changed now receives the whole spool again, where the reporter used to carry its cursor to the new server and skip every event behind it. To upgrade a seat, install the new `fleet-reporter.js`, then stop the flusher and let cron or the next hook start it (`INSTALL-LINUX.md` Step 1); every upgraded seat shows one `epoch_reset`, and until server card#12210 a seat whose last batch before the upgrade was committed but unanswered, or whose existing site is given a name other than `default`, shows a false `seq_gap` badge for 24 h (no event is lost or doubled). `docs/design/EVENT-SCHEMA.md` § 3.1 states every rule.
- **card#12187** — **A sleeping agent shows three larger z's above its head, lit in turn, its monitor is switched off, and the lobby directory reads on a phone.** An idle agent now draws three z's that stand still above and beside its head, on the side away from the way its head rolled, clear of its ears, leaves and caps, of the thought trail and of the desk's furniture, the lowest the largest: about 15, 12 and 9 CSS px tall at a 1,440-wide window's fit, against about 10 px for the largest before. A glow of the floor's lamp colour travels up them from the character, one z to the next every half second, a two-second cycle. Each moving loop on the floor starts at its own seat's point in the loop, so sleepers and typists at neighbouring desks move out of step; with reduced motion every sleeper is drawn still, all three z's at full brightness. An idle desk's monitor is drawn off — the unlit screen with no text, the state line staying on the desk's facts plate — and its list row and drill-down read *monitor off*. On the lobby, a window too small for the directory board to be read — phones, tablets, and laptop browser windows shorter than about 760 px at 1,440 wide — shows the floor directory and the building readings in the page under the drawn room, at the page's own text size, scrolled and pinch-zoomed with the page, each floor's name a tap target of at least 24 × 24 px; a larger window keeps them on the board. The lobby re-checks this on every window resize and every change of the browser's text size.
- **card#12212** — **Eight new characters join the floor: a penguin, a snail, a sheep and a deer, and a corn cob, a broccoli, a bell pepper and a cabbage.** Each is drawn to the same cute, painterly look as the first sixteen, in every pose a desk draws — standing and working, walking, the intern's small form, and asleep on the desk — with its own five colourways, hats, neckwear and things to hold. The new species join the one list every seat's character is drawn from, and the draw is re-seeded once over the grown list so that no room of the known fleet shows the same body twice — so with this upgrade nearly every seat gets a different character, from the full set of twenty-four. - **card#12179** — **The two-factor code page offers "Remember this browser for 30 days".** The authenticator-code form and the recovery-code form both have the box. Ticked when the code is accepted, it lets that browser sign that account in on its password alone for 30 days from the tick; using the browser does not extend the 30 days. Every other browser, and any other account signing in on that browser, is still asked for a code, and an unticked box signs in exactly as before. The browser holds a random token in a cookie marked `Secure`, `HttpOnly` and `SameSite=Lax`, so it is kept only over HTTPS, and the host stores only a hash of the token. Every remembered browser for an account is forgotten when its password changes, when its second factor is reset by email, disabled, re-enrolled or moved to a new authenticator, and when the account is retired; emptying the `remembered_browsers` table forgets them all at once. The upgrade's migration adds the table `remembered_browsers`. `README.md` § Remembering a browser describes it.
