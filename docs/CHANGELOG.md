# Changelog

Every PR whose title or branch carries a `card#NNNN` token owes a changelog note **in the same
PR** — and since card#12935 the note is a file of its own, `docs/changelog.d/<card>.md`, holding
the one line `- **card#NNNN** — …` exactly as it will appear here. **A change PR does not edit
this file**: two changes built side by side then never touch the same lines, so neither conflicts
with the other. A PR that names no card owes nothing. `docs/PLAN.md § 4` owns that rule and the
reasoning behind it, including why the bullet must be line-initial;
[`docs/changelog.d/README.md`](changelog.d/README.md) states the note's format;
`docs/VERSIONING.md` owns when a release gathers the notes into its section here.

⛔ **Enforced by `bin/release-pr-guard.py`**, on every PR. **R4** (since 2026-08-30 — for seven
days before that it was prose, and six cards' work merged with no entry at all) asks for the
note of every card the branch or title names; the two cases that owe nothing are a PR into `main`
(the release gathers the notes) and a PR that REMOVES a card's note (a revert of unreleased work),
both argued in that file's docstring. **R8** (card#12935) refuses a change PR that adds a line
under `## [Unreleased]` here, or that carries a malformed note. **R5** holds this file's SIZE under
`1 MiB − the bytes it grew in the last 14 days`, so it reds while there is still time to archive
released sections rather than after the contents API has begun returning it empty. **R6**
(card#9707) compares a release PR against `dev`, so a release cannot quietly ship with fewer
notes or cards than `dev` holds; it accepts the release deleting a note only when that note's line
is in the release's copy of this file. **R7** (card#9814) refuses a release PR whose copy of this
file carries more than two released sections, and so enforces the archiving below. **R9**
(card#12935) refuses a release PR that leaves a note in `docs/changelog.d/` unassembled.

Sections are newest-first. `## [Unreleased]` stays empty on `dev`: what has landed since the last
release is the set of notes in `docs/changelog.d/`, and a release writes them here as its own
section, highest card number first (`docs/VERSIONING.md § Release flow` step 4).

This file holds `[Unreleased]` and the latest released section only. Every older release is one
file per tag under [`docs/changelog/`](changelog/) — `ls docs/changelog/` lists them — moved there
verbatim by release flow step 13 (`docs/VERSIONING.md`), which R7 enforces. R5 gates this file's
size; `docs/PLAN.md § 4` says why the archive files need no gate of their own beyond R7's backstop.

## [0.16.0] — 2026-11-21

- **card#13521** — **A character walking back to its desk from the snack table or the restroom now thinks a fitting return thought.** On both the 2-D and the 3-D floor, the thought bubble a character carries on its way to a break changes, on the walk back, to a line picked at random for that break — refreshed and ready to get back to work — from one list for the snack table and one for the restroom; every viewer sees the same line for the same break, and the bubble goes when the character sits down.
- **card#13519** — **On a short or small browser window the lobby keeps its floor directory, building readings and event log on the board, in smaller text.** A laptop browser window of about 1,000 × 560 or 1,366 × 657 now shows the directory on the board at the top of the page, its text shrunk to fit the board (down to 0.6 of the page's text size, 9.6 px at the browser's default 16 px). The directory moves below the drawing only on a much smaller window: narrower than about 700 px, as on a phone, or shorter than about 455 px. A window at least about 1,150 px wide and 760 px tall shows the board exactly as before, at the page's own text size. The list still scrolls inside the board, and its links and keyboard focus work as before.
- **card#13258** — **Every subagent on the floor is now its own species: no two characters in the building, agents and subagents together, share a species until every species is in use, and a subagent keeps its species for as long as it runs.** The 2-D and 3-D floors draw each subagent in the species the server allocated for it, sitting at its desk's side table and walking to and from the elevator, the snack corner and the restroom. A subagent the server sends no species for is shown as missing art, in both views, and is reported as such. The feed version is now 4, so every open floor, lobby and building page reloads once after the deploy. On that reload a subagent already running may change animal once.
- **card#13258** — **The server now gives every intern (a subagent at a desk's side table) its own character, chosen like a seat's so no two characters in the building share a species until every species is in use.** A migration creates the `intern_species` table and backfills it in one transaction: each open intern is given a species by the same rules a new seat uses — over the live seats and the open interns together, never its own seat's species — and each closed dispatch call is given its key's first species that is not its seat's, so a `mezzanine:rebuild` finds a stored species for every call it replays and never re-draws one. The migration prints the open interns it allocated and the count of closed calls it wrote, and prints nothing on a store with no dispatch calls. `mezzanine:fold` runs the same backfill once when it starts, which covers interns the previous release's worker opened between the migration and the deploy's daemon restart; if that run fails it logs an error, counts `intern_species_seed_failed` on fleet health, and the worker folds on. A new seat now also avoids a species an open intern holds. The feed's seat object carries `subagents[].species`, `null` only when an open intern has no stored species, and both floors draw each intern in it. A stored species is purged 14 days after it was allocated, on the event log's retention.
- **card#13033** — **You can ride the elevator from the 3-D floor, and arrive on the next floor in 3-D.** Click the elevator's doorway, or Tab to it and press Enter or Space: its doors open and the same cab as on the 2-D floor opens, with every floor's button and the lobby's. Choosing a floor takes you to that floor's 3-D view; choosing the lobby takes you to the lobby. A drag that starts on the doorway still turns the view, and a ride begun on the 2-D floor still arrives on the 2-D floor.
- **card#13033** — **On the 3-D floor, what an agent is doing stands beside the agent instead of in front of it.** The line from an agent's screen and its task bubble now stand just to the right of the agent, as you see it, from every side you turn the camera to, so the agent itself stays in view; the task bubble sits directly above the screen's line, so both show together. Both sit on see-through plaques, so the room shows through them: the screen's line is white text on a dark plaque and the task bubble dark text on a light one, each readable against anything behind it. A character's thought on its way across the floor uses the same light plaque. Dragging on a screen line or a task bubble turns the view, as dragging anywhere else on the floor does. The names, state chips and facts cards look as before, and the 2-D floor is unchanged.
- **card#13033** — **On the 3-D floor, the elevator's open doors show the cab inside.** Behind the leaves stands the cab's room, its open front the doorway itself and running back a real cab's depth, so through the open doors you see its back corners, its side walls with their kick plates and handrails, the ceiling with its light, and the floor — in the same colours as the 2-D floor's cab, shaded deeper toward its back wall. The cab is seen only through the doors, as on the 2-D floor: from a raised view nothing of it shows above or beside the back wall.
- **card#13033** — **On the 3-D floor, a character entering the elevator stays in sight until the doors close.** A character or intern stepping into the cab is now seen standing inside it until the leaves have closed over it, and one arriving is seen inside the cab as the leaves open before it steps out, as on the 2-D floor; before, it vanished the moment it left the floor.
- **card#13033** — **On the 3-D floor, Page Up and Page Down raise and lower your eye, and so does Alt with a vertical drag.** The view keeps looking the same way from the same distance while the eye moves straight up or down, from the floor to the room's ceiling height (once the point you look at reaches the floor, Page Down lowers the eye on its own and the view tilts toward level); dragging with Alt held moves the room with the pointer. Every other control works as before, Shift with a left-drag still slides the view along the floor, and on the 2-D floor and the lobby Page Up and Page Down still scroll the page. The hint line under the 3-D floor lists the new controls.
- **card#13033** — **The 3-D floor now opens with the whole floor filling the width of your browser window.** The opening view, and *Fit the floor*, bring the camera in until the floor and its walls reach the left and right edges of the view, a few pixels in from each; in a window too short for that, the floor fills the height instead, so all of it stays in view. The camera's angle and the point it looks at are unchanged, and you can still zoom out as far as before.
- **card#13033** — **The 3-D floor is lit to show depth, and things sit on the floor.** The floor's boards now show the same colours as on the 2-D floor instead of washing out pale, and every desk, couch and piece of furniture shows its top, its front and its side in three distinct shades. A soft plum shade lies under each seated agent and intern (in place of the old hard dark circle), under each desk, couch and piece of furniture, and along the foot of every wall. The light follows the time of day the windows show: warm white by day, rosier at dawn and dusk, cool at night, and after dark each floor lamp throws a warm pool on the floor around it. On screens with very high pixel density the floor is drawn at twice the CSS resolution at most, which keeps it smooth on phones. One of the raccoon's colourways is a slightly deeper plum, on both floors, so it stays easy to tell from the grey-blue cat under the new light. Nothing moves or animates for any of this, and the 2-D floor is otherwise unchanged.
- **card#13033** — **On the 3-D floor you can walk into the office, and the back wall no longer drops.** Dragging with the right mouse button, sliding two fingers, or Shift with an arrow key now walks you forward into the office and across it, at the same height and facing the same way; the scroll wheel still zooms. To walk at desk level, lower your eye first with Page Down — from the opening view too: once the point you look at is on the floor, Page Down keeps bringing your eye down, tilting the view toward level, and Page Up takes it back up the same way. You stop at the back wall and at the two side walls and slide along them, so you always stay inside the office; turning or zooming out near a side wall brings the view in closer rather than through the wall. The back wall with the elevator now always stays up, however close you get. *Fit the floor* returns to the opening view from anywhere.
