- **card#12450** — **A seat's subagents arrive by the elevator and leave by it.** When a subagent starts, the elevator's doors open on its intern, which steps out, walks to its own place at the side table, sits, and its laptop fades in over a second; when it stops, the laptop fades out and the intern walks back to the elevator, waits there for up to a minute as a seat's character does, steps in, and the doors close behind it. - **card#12477** — **`bin/deploy.sh` works with git 2.56: every check that reads git's answer about a damaged or missing checkout gives the same verdict on git 2.56 as on earlier gits.** git 2.56 changed two answers the deploy reads. A `.git` file that points at no repository is now described as `gitfile does not point to a valid repository`, and the deploy refuses it as *not a git checkout*, as it does on earlier gits. A loose object the deploy user cannot open is now reported as corrupt, with exit 128, and `git fetch` stops on such a commit near the checkout's own branch tips: on git 2.56 the deploy refuses at its fetch with git's own message, and the fetch refusal names `git -C <deploy root> fsck` to find the object. A `--ref` whose resolution meets an unreadable object gets one refusal on every git version, whatever status git exits with. The deploy selftest suite (`bin/deploy.selftest.sh`) passes on git 2.53.0, 2.55.0 and 2.56.0, measured locally, and the deploy needs nothing new from the host.
- **card#12443** — **Each agent gets its own character.** The operator saw two seats of one floor wearing one body (2026-10-26) and ruled on the design on 2026-10-27 ("I accept your recommendations for all questions"). The server now chooses a seat's creature once, when its first token is issued: one no live seat is, while there are enough to go round; else one no live seat on its floor is; else the least used on its floor, then fleet-wide. The seat keeps it for life, retiring a seat frees it for the next new one, and a seat that moves to a different `(install_id, seat_id)` is a new seat with a new character. Every seat object carries it as `character.species`, the floor draws exactly that body, and an intern never wears its seat's. Interns are not counted for uniqueness. The console's *Agents* page lists each seat's character, read-only. `docs/design/FLEET-STATE.md § 6.13` and AT-D2-31 and `docs/design/FLOOR.md § 3.1`, § 5.1, § 10.4 and AT-D3-24 describe the behaviour; `ASeatsCharacterIsAllocatedOnceTest`, `TheCharacterMigrationKeepsEveryUniqueDrawTest`, `SeatCharacterAllocationLockOrderTest`, `TheSpeciesListHasOneSourceTest` and the painter probe's body legs hold it. **Deploy:** the deploy's `migrate` adds `seats.species` and `seats.species_drawn_at` and a one-row `species_allocation_lock` table, and gives every existing seat a character: each live seat keeps the body it draws today unless an earlier live seat draws the same one, in which case the later seat moves, and the migration prints each move, before and after, and logs it. A seat already retired is given the body its key draws today, which the *Agents* page labels *today's draw*. The feed's `feed_version` moves to 2, so a floor or lobby page open across the deploy shows the reload banner; reloading it draws the new bodies. Rolling the migration back drops the two columns and the table.
